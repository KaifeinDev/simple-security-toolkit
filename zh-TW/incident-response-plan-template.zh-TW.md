## 事件啟動

任何成員發現以下訊號時，應立即通知事件指揮官（或代理人），由其判斷是否啟動本計畫：

- 監控警示觸發（大額異常轉出、不變量被打破、oracle 異常等）
- 資安信箱／bug bounty 收到高嚴重度回報
- 社群或社群媒體出現疑似攻擊的討論
- 團隊成員自行發現可疑交易

## 立即應變步驟

- [ ] **檢視漏洞攻擊交易**，找出漏洞所在 - **[*負責人*]**（目標：60 分鐘內有初步結論）
    - 目標是回答三個問題：**攻擊如何運作？哪些合約與資金受影響？攻擊是否仍在進行或可被重複？**
    - 使用工具：
        - [Phalcon Tx Explorer](https://explorer.phalcon.xyz/)
        - [Foundry 交易重放追蹤/除錯工具](https://book.getfoundry.sh/reference/cast/cast-run.html#cast-run)（`cast run <tx_hash>` 可重放並追蹤交易）
        - [Tenderly Debugger](https://dashboard.tenderly.co/tx/mainnet/0xf427afc17bd30a84f4b47dc2eaa176115cf28bdea1110245d3b0948ca3b6595c/debugger)
    - 將攻擊交易 hash、攻擊者地址、初步分析結論即時記錄在作戰室（事後檢討也需要這些紀錄）。
- [ ] **暫停合約**（若可行）、採取其他防禦性行動，並考慮採取攻擊性行動（例如白帽搶救）- **[*負責統籌的人*]**（目標：確認漏洞後 30 分鐘內完成防禦動作）
  - 判斷順序：(1) 能暫停就先暫停受影響合約；(2) 評估連帶風險決定是否擴大暫停範圍；(3) 若資金仍暴露且無法暫停，評估白帽搶救（由自己人先把資金安全轉出）。
  - 步驟：
    - **[*由誰、如何進行、涉及哪些地址*]**
    - 緊急腳本位置：**[*repo 路徑或文件連結*]**
    - 多簽簽署者與門檻：**[*名單與人數*]**
  - 審查交易 - **[*負責人，應與建立該交易的人不同*]**
    - 緊急狀態下最容易發生「防禦交易本身出錯」或簽到釣魚交易。複核者需獨立確認：目標地址正確、calldata 符合預期、不會造成新的損害。
  - 您絕對不會希望在事發當下才手忙腳亂地搞清楚誰有權簽署以採取防禦性行動。強烈建議使用 [OpenZeppelin Defender](https://www.openzeppelin.com/defender)，並依照[上線前資安檢查清單](https://github.com/nascentxyz/simple-security-toolkit/blob/main/zh-TW/pre-launch-security-checklist.zh-TW.md)事先準備好可部署的防禦性行動腳本。
- [ ] **審查所有合約**，找出可能的連帶漏洞。視需要暫停相關合約 - **[*負責人*]**
  - 逐一檢查：使用相同漏洞模式的其他合約、與受影響合約共用狀態或資金的合約、依賴受影響合約輸出（價格、餘額）的下游整合。
  - 產出一份「已檢查合約清單」，標注每個合約的狀態（安全／已暫停／觀察中）。
- [ ] **更新前端介面 (UI)**，以反映目前狀態 - **[*負責人*]**
  - 停用會導致使用者資金流入受影響合約的功能，並在明顯位置放上狀態公告。
- [ ] **聯繫資安合作夥伴** - **[*負責人*]**
  - **[*過往審計人員清單及其聯絡方式，或共用頻道位置*]**
    - 您的審計人員會希望在其能力範圍內提供協助，即使主要目的是為了維護自身聲譽
  - 請勿讓任何不在您信任圈內的人進入作戰室
  - 即使攻擊者已成功將資金轉出，也不要假設被竊資金已無法追回。請立即聯繫可信賴的相關人士，包括知名資安專家或您的創投投資人，請他們協助引介相關的執法機關聯絡窗口、資產追蹤專家及資金追回服務
    - 資金追蹤第一步：記錄攻擊者地址並通知主要交易所與穩定幣發行方（USDT/USDC 可凍結黑名單地址），時效性極高，越快越好。
- [ ] **通知使用者**，透過相關社群媒體管道發布訊息。Discord：**[*負責人*]**，Twitter：**[*負責人*]**（目標：確認事件後 1–2 小時內發出首則公告）
  - 首則公告建議內容：確認發生事件、正在調查、使用者當下該做／不該做什麼（例如停止與合約互動、撤銷 approve）。**不要**在事實釐清前猜測損失金額或承諾賠償。
  - 一有實質新資訊或進展，即定期更新
    - 即使沒有新消息，至少每 24 小時更新一次，也有助於讓社群安心，讓大家知道您正在積極處理此事
    - 所有對外訊息都應先經過漏洞審查人員把關，確保不會無意間洩漏可能危及資安的資訊，或在所有事實尚未釐清前，就對特定補救措施做出承諾
  - 提防事件期間的二次攻擊：攻擊發生後常出現假冒官方的釣魚公告（假「賠償網站」、假「緊急撤資工具」）。在官方公告中明確提醒使用者只信任固定官方管道。
